# The Liquidation of Penny

금융 개념을 전투와 성장으로 구현한 2D 횡스크롤 액션 로그라이트 브라우저 프로토타입.
기준 저장소: https://github.com/ryemso/The-Liquidation-of-Penny

## Chapter 01 Vertical Slice

현재 작업 브랜치에서는 **1장 `잡주의 골목` 한 판을 처음부터 끝까지 완주 가능한 Vertical Slice**로 고정합니다.

플레이 흐름:

`폐장 골목 → 손절 교차로 → 공칠의 거래소 → 폐쇄 거래소 → 작전세력 소굴 → SMALL CAP 승격`

- 폐장 골목: 기본 공격, 수익 축적, 익절을 익히는 첫 전투
- 손절 교차로: 폭탄·원거리 적과 2단 점프/대시 회피
- 공칠의 거래소: 시드를 사용한 회복 및 종목 편입
- 폐쇄 거래소: 상층 탐험, 차트 토템, 선택형 엘리트 도전
- 작전세력 소굴: `잠식된 선동가` 보스전 및 1장 클리어
- 보스 클리어 후 2장으로 넘어가지 않고 `PENNY STOCK → SMALL CAP` 결과 화면으로 한 판이 종료됩니다.

브라우저 진입점은 `vertical-slice-bootstrap.mjs`이며, 기존 `engine.mjs`의 1장 콘텐츠를 그대로 사용하고 Vertical Slice 종료 규칙만 별도 모드로 적용합니다.

## 조작과 실행

← → 이동 / C 두 번 점프 / X 기본 3단 공격 / Z 무적 대시 / A 익절 / S 레버리지 / D 서킷브레이커 / ↑ 출구·상점 / I 토템 / Esc 일시정지.

루트에서 `python -m http.server 8000` 실행 후 `http://localhost:8000` 접속.
테스트: `node --test tests/*.test.mjs`.

## Vertical Slice 완료 기준

- 1장 5개 구역을 순서대로 플레이할 수 있음
- 일반 전투 → 보상 선택 → 상점 → 엘리트/탐험 → 보스의 서로 다른 플레이 경험이 연결됨
- 보스 처치 전에는 마지막 출구를 사용할 수 없음
- 보스 처치 후 출구에서 상호작용하면 1장 승리 처리
- 2장 콘텐츠로 자동 진행하지 않음
- 최종 랭크가 `SMALL CAP`으로 표시됨
- 기존 플레이 로그, 토템, 보상, 시장 상태 시스템을 유지함

## 현재 전체 콘텐츠

원본 엔진에는 이후 확장용 2장 `기관의 벽`, 3장 `알고리즘의 심장` 콘텐츠도 남아 있습니다. Vertical Slice 모드에서는 1장 종료 시 접근을 차단합니다. 기존 3장 전체 프로토타입 로직을 삭제하지 않았기 때문에, 향후 Vertical Slice 검증 뒤 다시 전체 캠페인으로 확장할 수 있습니다.

## 차트 토템

차트 토템은 최대 3종을 장착합니다. 획득·교체·형성·실패·발동 로그가 기록되며, 1장 탐험 루트와 선택형 엘리트 보상에서 실제 빌드 선택으로 사용됩니다.

## 플레이 분석

`analytics.mjs`가 run_id, stage_id, chapter, 시뮬레이션 시간, 실제 시각, 체력, 시장, 장착 토템을 공통 필드로 기록합니다. 전투·보상·탐험·엘리트·사망·클리어 이벤트를 연결해 Vertical Slice 플레이테스트에 사용할 수 있습니다.

## 검증

기존 회귀 테스트에 더해 `tests/vertical-slice.test.mjs`가 다음을 검증합니다.

- 1장 이후 방으로 진행되지 않는지
- 보스 클리어 출구가 Vertical Slice 승리로 종료되는지
- 잠긴 보스 출구로 조기 종료할 수 없는지

실제 사람의 입력 체감·가독성·난이도는 별도 플레이테스트가 필요합니다.
