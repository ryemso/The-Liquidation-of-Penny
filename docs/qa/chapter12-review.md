# 1·2장 진행과 기존 토템 5종 점검

기준 커밋: `0fb1d6b4a380da347d335e49c5b73688de2a001b` (main).

## 판정과 한계

**엔진 통합 검증 완료 / 실제 브라우저 플레이 검증 미완료.**

게임을 로컬 HTTP 서버로 실행했으나 Cloud Browser의 로컬 주소 접근 정책에 막혔다. 실제 캔버스 화면, 키 입력 체감, 선택창 가독성, 음악, 다운로드 버튼 동작은 확인하지 못했다. 이 문서와 JSON은 사람의 플레이 기록이나 브라우저 E2E 결과가 아니다. 3장 확장 승인 근거로 사용하지 않는다.

기존 테스트 38개는 통과했다. 추가한 통합 테스트 27개를 포함해 총 65개가 통과한다. 엔진의 `action()`과 `update()`를 통과하는 입력 시뮬레이션을 추가했고, 기존의 직접 토템 신호 호출 테스트와 구분했다.

## 검증 방법

- 연속 진행: 새 Game, 지식 0, 기본 체력·공격력으로 시작. 60Hz 입력. 좌우 이동·점프·대시·공격·스킬·출구 상호작용과 실제 보상/상점 메서드를 사용한다. 순간이동, 적 강제 처치, 체력·공격력 보정, 방 강제 이동은 하지 않는다.
- 고정 시드 1·2·3에서 기본 진행과 적극 탐험을 각각 실행했다. 기본 진행도 우연히 닿은 상자를 선택할 수 있으므로 엄밀한 무탐험 대조군은 아니다.
- 적극 탐험: 기본 적 처치 후 발판을 올라가 상자와 접촉, 토템 선택·장착, 숨은 상자 발견, 선택형 드론 도전·회수까지 진행한다. 신규 토템 획득 시 빈 슬롯, 없으면 1번 슬롯을 교체한다.
- 토템 개별 검증: 위치를 초기 설정한 정지 보스와 생성한 적대 투사체를 쓰는 통제된 엔진 전투이다. 토템 보유·장착은 fixture로 준비한다. 이후 형성 진행이나 대기시간을 직접 설정하거나 `TotemSystem.signal()`을 호출하지 않는다. 실제 보스 AI를 상대하며 5종 모두 발동했다는 의미는 아니다.
- 2장 완료 뒤 3장 첫 방 진입까지만 확인한다. 그 시점의 중간 로그이므로 `run_end`가 없고 stage_start는 11, stage_clear는 10이다. 완료율 10/11은 실패나 이탈이 아니다.

## 재현한 결함과 수정

**폭탄 자폭 처치 로그 누락**

기본 진행 시드 1에서 처치 수는 26인데 enemy_defeated는 25였다. `explode()`는 사망·처치·시드 보상을 처리하면서 처치 로그를 남기지 않았다. 별도 자폭 fixture에서도 예상 로그 1개가 실제 0개로 실패했다.

수정: 자폭 시 적 ID·종류·optional과 `cause: self_explosion`을 포함한 enemy_defeated를 기록한다. 이미 사망한 적의 재호출은 무시하여 중복 처치·보상·로그를 막는다. 공격력, 보상량, 적 패턴은 변경하지 않았다. 수정 후 연속 진행 6회의 처치 수와 처치 로그 수가 일치한다.

## 추가 11종과 조합 검사

`tests/expanded-totems-integration.test.mjs`는 표시 설명에서 별도로 작성한 입력 순서를 사용한다. 구현의 sequence 배열을 읽어 동일 신호를 주입하지 않는다. 정지 보스·초기 수익 100·초기 체력 50·생성 투사체는 명시적 fixture 조건이다.

- 삼중 바닥/천장, 둥근 바닥/천장, 머리어깨형/역머리어깨형, 콰시모도, 상승/하락 쐐기, 대칭 확산형, 울프웨이브: 각 1회 발동 및 대기시간 진입.
- 각 토템 해제→재장착 후 대기시간 유지, 메뉴에서 시간 정지.
- 둥근 바닥 + 둥근 천장 + 깃발형: A 후 회복이 정확히 15, 대상 공격 약화 8초. A를 반복 요청해도 추가 회복 없음.
- 삼중 바닥 + 역머리어깨형 + 콰시모도: 각각 1회, 총 3회 발동. 추가 피해가 토템 신호로 재귀 전파되지 않음.

이는 전 조합 완전 검증이 아니다. 특히 슬롯 순서에 따른 대상 사망, 광역 타격의 여러 대상, 모든 회복 조합의 장기 반복은 후속 검증 대상이다.

## 추가 로그 결함과 수정

폭탄이 플레이어와 주변 적을 동시에 죽이는 fixture에서 마지막 이벤트가 run_end가 아닌 enemy_defeated였고, finish 콜백에서 직렬화한 아카이브는 주변 적 처치를 누락했다.

- 폭발의 주변 적 피해를 먼저 처리한 뒤 플레이어 피해·사망 처리를 수행한다. 동시 폭발 처치가 사망 아카이브에 포함된다.
- `RunLog.end()`가 종료 이벤트를 남긴 뒤 로그를 닫고, `add()`는 종료된 도전의 후속 이벤트를 거절한다.
- 치명적 폭발에서 처치 2개·사망 1개·종료 1개를 확인하고, 종료 콜백의 JSON과 이후 export가 동일함을 검사했다.
- 재시작 사유로 종료 후 늦게 도착한 공격과 중복 종료 요청은 로그를 바꾸지 않으며, 새 Game은 다른 run_id를 갖는다.

위 검사는 엔진 직렬화 검사다. 브라우저 localStorage와 실제 파일 다운로드 동작을 검증한 것은 아니다.
